════════════════════════════════════════════════════════
BUG 1 — lastBlockedPkg cooldown survives HOME navigation
════════════════════════════════════════════════════════

Root cause:
When a blocked app fires, `lastBlockedPkg = pkg` and `lastBlockedAtMs = now`.
The service fires GLOBAL_ACTION_HOME. The launcher fires TYPE_WINDOW_STATE_CHANGED
and hits the BLOCKABLE_AFTER_WARNING early-return at the bottom of that block (line ~1049),
which returns WITHOUT clearing lastBlockedPkg.

On the next open of the same blocked app (within 2 seconds):
  val samePackage    = pkg == lastBlockedPkg   // true
  val cooldownExpired = (now - lastBlockedAtMs) > 2_000L   // false
  if (!samePackage || cooldownExpired) { /* block */ }
  // → false, block silently skipped

Fix:
In `onAccessibilityEvent`, find the NEVER_BLOCK early-return block. It currently reads:

    if (NEVER_BLOCK.any { pkg.equals(it, ignoreCase = true) }) {
        return
    }

Change it to:

    if (NEVER_BLOCK.any { pkg.equals(it, ignoreCase = true) }) {
        // User navigated to a safe/home package — reset the block cooldown so
        // the next open of the previously blocked app is caught immediately.
        lastBlockedPkg = null
        lastBlockedAtMs = 0L
        return
    }

Rationale: NEVER_BLOCK contains all home launchers. WhatsApp is also in the set but
resetting on WhatsApp is also correct (user went to a different app). This is safe because
the cooldown's only purpose is to de-duplicate rapid re-fires within the same foreground
session; after the user has visited any NEVER_BLOCK package, they have genuinely left
the blocked app.

BUG 2 — No active watchdog (service is 100% event-driven)
════════════════════════════════════════════════════════

Root cause:
TYPE_WINDOW_STATE_CHANGED is not guaranteed to fire when the same Activity is brought
back to the foreground via recent apps without recreation. If that happens, the service
never sees the blocked app return and doesn't block it.

Fix: Add a periodic foreground-app watchdog that runs every 1500ms.

Step 1 — Add a class-level field near the other Runnable fields:

    private var foregroundWatchdogRunnable: Runnable? = null

Step 2 — Add these two private functions anywhere in the class:

    /**
     * Polls for the foreground package via UsageStats and enforces blocking
     * if the app that is currently visible should be blocked. This catches
     * cases where Android does not fire TYPE_WINDOW_STATE_CHANGED (e.g. the
     * same Activity returning via recent apps without recreation).
     */
    private fun checkForegroundNow() {
        val usm = getSystemService(UsageStatsManager::class.java) ?: return
        val now = System.currentTimeMillis()
        val events = usm.queryEvents(now - 3_000L, now)
        val event = UsageEvents.Event()
        var latestPkg: String? = null
        val fgType = if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.Q)
            UsageEvents.Event.ACTIVITY_RESUMED
        else
            UsageEvents.Event.MOVE_TO_FOREGROUND
        while (events.hasNextEvent()) {
            events.getNextEvent(event)
            if (event.eventType == fgType) latestPkg = event.packageName
        }
        val pkg = latestPkg ?: return
        if (pkg == packageName) return
        if (NEVER_BLOCK.any { pkg.equals(it, ignoreCase = true) }) return
        if (BLOCKABLE_AFTER_WARNING.any { pkg.equals(it, ignoreCase = true) }) return

        val focusActive  = prefs.getBoolean(PREF_FOCUS_ON,    false).let { on ->
            if (!on) false else (prefs.getLong("task_end_ms", 0L).let { e -> e <= 0L || now < e })
        }
        val saActive     = prefs.getBoolean(PREF_SA_ACTIVE,   false).let { on ->
            if (!on) false else (prefs.getLong(PREF_SA_UNTIL, 0L).let { u -> u <= 0L || now < u })
        }
        val alwaysBlock  = prefs.getBoolean(PREF_ALWAYS_BLOCK, false)
        if (!focusActive && !saActive && !alwaysBlock) return

        val blocked = isPackageBlocked(pkg, focusActive, saActive, alwaysBlock)
        if (!blocked) return

        val samePackage    = pkg == lastBlockedPkg
        val cooldownExpired = (now - lastBlockedAtMs) > 2_000L
        if (!samePackage || cooldownExpired) {
            lastBlockedPkg  = pkg
            lastBlockedAtMs = now
            handleBlockedApp(pkg, explicitBlockReason(pkg, focusActive, saActive, alwaysBlock))
            scheduleRetryCheck(pkg, 1, focusActive, saActive, alwaysBlock)
        }
    }

    private fun startForegroundWatchdog() {
        val r = object : Runnable {
            override fun run() {
                try { checkForegroundNow() } catch (_: Exception) { }
                handler.postDelayed(this, 1_500L)
            }
        }
        foregroundWatchdogRunnable = r
        handler.postDelayed(r, 1_500L)
    }

Step 3 — Start the watchdog in onServiceConnected(), after the existing setup calls:

    startForegroundWatchdog()

Step 4 — Stop the watchdog in onInterrupt(), alongside the existing cleanup:

    foregroundWatchdogRunnable?.let { handler.removeCallbacks(it) }
    foregroundWatchdogRunnable = null

BUG 3 — Keyword blocker: same watchdog gap
════════════════════════════════════════════════════════

The keyword blocker (handleTextChanged, handleContentChanged) calls handleBlockedApp
directly and has no mechanism to re-check if the same browser page is still visible
when the app returns via recent apps.

Fix: The foreground watchdog from Bug 2 addresses this for fully blocked packages.
For keyword-blocked content inside an otherwise-allowed app (e.g. YouTube Shorts
inside YouTube), extend checkForegroundNow() to also call the content-specific
guards (blockYoutubeShorts, blockInstagramReels) by adding the following at the end
of checkForegroundNow(), after the `if (!blocked) return` check fails — i.e. in an
else branch:

    } else {
        // App is not fully blocked — but check content-specific guards
        // so that Shorts/Reels blocks survive a recents-app return.
        val blockYoutubeShorts  = prefs.getBoolean(PREF_BLOCK_YT_SHORTS,  false)
        val blockInstagramReels = prefs.getBoolean(PREF_BLOCK_IG_REELS, false)
        if (blockYoutubeShorts && pkg == "com.google.android.youtube") {
            // Can't re-scan window content from here without an event — reset
            // lastSeenPkg so the next window-content event is guaranteed to re-check.
            if (lastSeenPkg == pkg) lastSeenPkg = null
        }
        if (blockInstagramReels && pkg == "com.instagram.android") {
            if (lastSeenPkg == pkg) lastSeenPkg = null
        }
    }

Note: Full keyword re-scanning from the watchdog is NOT possible without an
AccessibilityEvent (no way to pull the live node tree). The practical mitigation is
ensuring the window-content throttle (`lastContentScanMs`) is reset so the next
TYPE_WINDOW_CONTENT_CHANGED event triggers a fresh scan immediately. Add this to
checkForegroundNow() when a content-only block might apply:

    lastContentScanMs.remove(pkg)

CORRECTNESS GUARDS — do not break these existing mechanisms
════════════════════════════════════════════════════════

1. Do NOT touch `currentTimedPkg` in any of the above fixes. It is exclusively for
   timed-allowance apps (daily count / time_budget / interval modes) and has its own
   correct lifecycle. Modifying it would corrupt allowance tracking.

2. The `block_cooldown_reset` SharedPreference mechanism already works correctly when
   the user taps the overlay's own nav buttons (Back/Home). Do not change that code.

3. The `lastSeenPkg` field is used by scheduleRetryCheck to guard retries. The Bug 2
   watchdog must NOT update lastSeenPkg — let it remain the last event-driven value so
   retry guards are unaffected.

4. The RETRY_INTERVAL_MS × attempt retry chain (max 5 attempts = 750ms) must not be
   fired from checkForegroundNow() more than once per block. The samePackage +
   cooldownExpired guard already prevents this.

5. UsageStats ACTIVITY_RESUMED events on some OEMs have up to ~1s lag. The 1500ms
   watchdog interval is chosen to be larger than this lag so stale events don't trigger
   false blocks. Do not reduce it below 1000ms.
