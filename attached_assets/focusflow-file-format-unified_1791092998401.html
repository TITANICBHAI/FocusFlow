3. Tasks

FieldTypeCanonical rule
idstringNon-empty stable identifier; max 128 chars; unique within the file; no control characters.
titlestringNon-blank; max 1,000 chars.
descriptionstringEmit explicitly; "" is valid. Missing/null are normalized to an empty string when read.
startTimestringISO-8601 instant. Generator should emit UTC Z.
endTimestringISO-8601 instant, never before startTime.
durationMinutesintegerWhole minutes. Current V1 parser accepts 0–100000; generator should derive from timestamps and keep it mathematically consistent.
statusenumscheduled, active, completed, skipped, overdue.
priorityenumlow, medium, high, critical.
tagsstring[]Up to 100 tags/task; each tag up to 100 chars.
remindersReminder[]Reminder objects. Up to 100/task in current Kotlin V1.
colorstringTask color string. Parser allows up to 32 chars; common values are listed below.
focusModebooleantrue enables task-time focus blocking behavior. Missing defaults to false.
focusAllowedPackagesarray / null / absentAbsent or null = inherit global setting. Non-empty array = task-specific allow-list. Empty array has explicit block-all semantics and should not be used casually.
createdAtstringISO-8601 instant.
updatedAtstringISO-8601 instant.

Task invariants

task.id is unique within the file
endTime >= startTime
durationMinutes = (endTime - startTime) / 60_000
all task timestamps parse as instants
status and priority are known enums
Past scheduled task: when an imported task is scheduled but its endTime is already before the captured import now, the target restore contract normalizes it to skipped and does not create a future alarm for it. Historical completed, skipped, and overdue states are not rewritten by that rule.

Optional task fields are optional on read, explicit in canonical output

The current V1 reader supplies defaults for omitted description, tags, reminders, color, and focusMode. A generator should still emit them so the file is self-describing and deterministic.

4. Reminders

Reminder data is an array of objects. It is not an array of integer offsets.

{
  "id": "reminder-001",
  "taskId": "task-001",
  "offsetMinutes": -5,
  "type": "pre-start",
  "notifId": "optional-device-id"
}
FieldRule
idNon-empty stable reminder identity; max 128 chars.
taskIdParent task ID. Restore rewrites this when a parent task ID is remapped.
offsetMinutesInteger offset relative to the task schedule. Preserve exactly.
typepre-start, at-start, or post-start.
notifIdOptional/null. Treat as device-derived notification bookkeeping unless explicitly preserved by the exporter; do not invent one solely to make the object look complete.
Persistent data ≠ Android registration. A Reminder object is task data. It is not automatically a one-to-one representation of an Android AlarmManager alarm or notification request.

5. Focus Mode & package semantics

Global allow-list
{"allowedInFocus":["com.android.phone","com.whatsapp","com.example.music"]}
Per-task override
{"focusMode":true,"focusAllowedPackages":["com.whatsapp","com.example.music"]}
Task field stateEffective meaning
AbsentUse settings.allowedInFocus.
nullNo task-specific override; use the global setting.
Non-empty arrayUse the task-specific allow-list.
[]Explicit empty effective allow-list. The native focus path maps an empty effective list to com.focusflow.internal.blockall, so non-protected foreground apps can be blocked.
Do not document [] as “all apps allowed”. That wording existed in older UI/source comments, but it does not match the effective enforcement behavior. Omit the field when inheritance is intended.

Package references are exact Android package IDs. Label/name similarity is not a valid portability mechanism.

Presence-sensitive setting

focusMirrorVpnEnabled is presence-sensitive. When present, the imported value wins. Do not combine it with the local value using logical OR or another “keep true” merge.

Collection semantics

Portable settings collections listed above are replaced as a collection under the V1 restore policy rather than being blindly unioned. A future format version may introduce explicit per-field policies, but the V1 contract should not invent them.

The current TS exporter uses these descriptive section IDs:

focus-modestandalone-blockalways-ondaily-allowancekeyword-blockerblock-schedulesdefense
{
  "id": "focus-mode",
  "name": "Focus Mode",
  "configured": true,
  "appPackages": [

  ],
  "itemCount": 2,
  "details": {
    "allowedAppPresets": []
  }
}

Possible fields include id, name, configured, optional appPackages, optional vpnPackages, optional itemCount, and optional descriptive details.

Descriptive only: presetSections describe what the backup contains. They do not activate blocking, resurrect timers, or override the user's import choices.

11. Time & timezone

Absolute task timestamps

  • Use ISO-8601 instants.
  • Canonical generated form: UTC with Z, e.g. 2026-09-01T01:30:00.000Z.
  • The V1 reader accepts explicit offsets and normalizes them to the same instant.
  • exportedAtHuman is display text, not timezone authority.
Local ISTFile UTC
07:0001:30Z
10:0004:30Z
22:3017:00Z

Recurring schedules

Recurring schedules are wall-clock rules. Preserve the explicit schedule data and let the destination device apply it in its local schedule context. The current V1 format does not introduce an authoritative stored timezone field for these recurring rules.

Do not compare timestamps as arbitrary strings. Parse instants, compare instants, and calculate durationMinutes from the timestamp difference.

Strict input rules

  • Invalid UTF-8 is rejected; do not silently repair malformed bytes.
  • Duplicate JSON object keys are rejected before accepting the document.
  • Standard JSON only: no comments and no trailing commas.
  • Unknown optional fields may be tolerated for compatible V1 reads.

Enum safety

Unknown enum values must not silently fall back to a default meaning. Reject the affected incompatible value/object at validation/planning time.

      ↓

Merge

Incoming task IDLocal stateResult
Not present—Preserve incoming ID.
PresentSemantically equivalent projectionDuplicate/skip.
PresentMaterially different projectionExplicit ID_CONFLICT; do not let Room INSERT OR IGNORE decide semantics.

Duplicate task IDs inside the incoming backup are malformed/conflicting input and must be rejected before mutation. A deliberate re-import is otherwise allowed; there is no blanket “backup was already imported” dedupe requirement.

Task duplicate projection

The semantic comparison should canonicalize the task fields that define task identity/content, including reminder semantics. A reminder's own id is independent identity; when a parent task ID is remapped, update the reminder's taskId reference.

Replace

Replace changes the complete task-owned persistent graph as defined by the app contract. It does not mean “replace every setting, security field, runtime flag, live focus session, or OS registration.” Derived scheduling is reconciled separately.

Settings

Matching portable fields follow their field-specific policy. Omitted fields remain local. Runtime/device-local fields never become active because they happened to appear in an old file.

Active session guard: importing “replace” while an active focus session exists is a prohibited mutation in the target restore contract. Portable settings may be imported without restoring an active session; the session object itself is never serialized into V1.

Atomicity and recovery contract for implementers

A restore implementation should be modeled as a durable state machine rather than a chain of UI calls:

PREPARED → MUTATING → STORES_COMMITTED → RECONCILING → COMPLETED
          ↘ ABORTED_PRE_MUTATION
          ↘ RECOVERY_BLOCKED / RECOVERING

The durable RestorePlan is the exact target plan. Startup recovery should execute the persisted plan, not re-plan from changed device state. A global persistence write gate should block normal task/settings/maintenance writers while restore is active.

Scheduler registry: desired FocusFlow-owned alarm/scheduler identities belong to the persistent restore target. The registry describes what FocusFlow intends to own; it is not proof that Android currently has a matching AlarmManager registration.

16. Export semantics

Canonical export includes portable settings, all task records, descriptive presetSections, derived summary counts, and export metadata.

  • Task timestamps are canonicalized to UTC Z.
  • Suggested filename: focusflow-2026-09-01T14-30-00.focusflow.
  • Android transport uses SAF document creation and application/octet-stream.
  • Writing the file is successful when the provider write completes; automated readback verification is recommended.

Do not export these as authoritative runtime state

Active alarm registrations, active focus sessions, live notification permission/channel state, current foreground app, or the device's live blocking state are derived/local concerns.

18. Builder / generator rules

Builder capabilities

  1. Canonical starter template.
  2. Full-feature example.
  3. Validator using the published V1 rules.
  4. Section-aware controls or reusable templates.
  5. Human-readable validation errors.
  6. Download with .focusflow extension.
  7. No network upload.

Generate canonical data, not merely accepted data

  • Always emit version: 1.
  • Emit canonical UTC Z timestamps.
  • Emit reminders as objects.
  • Calculate summary from payload.
  • Exclude runtime-only state.
  • Do not invent notifId.
  • Keep recurring schedules and greyout windows separate.
  • Preserve absent/null/empty focusAllowedPackages semantics.

Embedded quick builder

20. Do-not-make-these-mistakes

✓
Do not turn .focusflow into a ZIP, SQLite dump, or binary database backup.
✓
Do not replace public TS-stable wire names with Kotlin internal property names.
✓
Do not encode reminders as integer offsets.
✓
Do not use presetSections as live activation instructions.
✓
Do not serialize the active focus session as if it were portable.
✓
Do not treat AlarmManager registrations as persistent backup truth.
✓
Do not invent notification IDs to make reminder objects look complete.
✓
Do not merge greyoutSchedule and recurringBlockSchedules.
✓
Do not use summary as the source of truth.
✓
Do not use app labels as package identity.
✓
Do not casually emit an empty focusAllowedPackages list.
✓
Do not claim every persisted Reminder object directly schedules one Android notification.
✓
Do not silently reinterpret unsupported legacy settings as active Kotlin features.
✓
Do not claim import restores live alarms or active blocking sessions verbatim.

22. What “valid” actually means

Format valid

JSON and schema constraints pass.

Import safe

The content can be normalized and planned without malformed/unsupported restore behavior.

Product semantically correct

The fields describe the intended FocusFlow behavior: portable persistence is portable, runtime state stays local, derived scheduling is rebuilt, and package/schedule/time semantics are preserved.

The third level is the actual target for canonical files and builders.

FocusFlow .focusflow V1 — unified reference. Keep this page and any interactive builder synchronized. When the V1 wire contract changes, update the canonical specification first, then the reference and validator together.

The page intentionally separates file semantics from Android runtime behavior. OS registration, notification presentation, exact-alarm capability, and full-screen intent behavior are derived platform state; they are not portable file fields.
