1. File structure

Only a few top-level fields are structural. Metadata and summaries are optional and non-authoritative.

Minimum valid V1 file

{
  "kind": "FocusFlowBackupV1",
  "version": 1,
  "settings": {},
  "tasks": []
}

JSON rules

  • Encoding: valid UTF-8. A leading UTF-8 BOM may be stripped by the importer.
  • Syntax: normal JSON; no comments or trailing commas.
  • Duplicate keys: rejected anywhere in the JSON object tree.
  • Unknown fields: compatible unknown fields may be accepted, but are not guaranteed to be portable.
  • Extension: use .focusflow; the extension alone does not make invalid content valid.
Top-level fieldTypeRequired?Meaning
kindstringYESMust be exactly FocusFlowBackupV1.
versionintegerOPTIONAL INPUTV1 is 1. Missing means 1; any present value other than 1 rejects the file.
exportedAtstringoptionalExport timestamp. Canonical form: UTC .sssZ.
exportedAtHumanstringoptionalHuman-readable timestamp. Informational only.
appVersionstringoptionalSource app version. Not the schema version.
platformobjectoptionalInformational metadata. Current exporter uses {"os":"android"}.
settingsobjectYESPortable settings payload.
tasksarrayYESTask records. The real task count is tasks.length.
presetSectionsarrayoptionalDescriptive export inventory. Never use it as live configuration.
summaryobjectoptionalInformational counts only. Never authoritative.
Do not treat summary as truth. A summary can say there are 12 tasks, but the actual records are still the objects in tasks.

2. Tasks

Tasks are the main portable records. Generate them consistently; read their fields literally.

FieldTypeRules
idstring1–128 chars, no control chars. Must be unique within the file. Current FocusFlow IDs are commonly ~21-character nanoid-style values.
titlestringNon-blank. Max 1,000 chars.
descriptionstring / nullMissing or null becomes "". Max 20,000 chars.
startTimestringISO-8601 with Z or explicit offset. Store/export as UTC .sssZ.
endTimestringSame timestamp rules. Must be ≥ startTime.
createdAtstringISO-8601; canonical output is UTC .sssZ.
updatedAtstringISO-8601; canonical output is UTC .sssZ.
durationMinutesinteger0..100000. A canonical builder should keep it consistent with the start/end times.
statusstringscheduled, active, completed, skipped, overdue.
prioritystringlow, medium, high, critical.
tagsstring[]Up to 100 per task; each up to 100 chars.
remindersobject[]Persistent but inert scheduling data. See reminder section below.
colorstringMax 32 chars. Missing defaults to #6366f1. Hex is recommended, but V1 does not require a strict hex grammar.
focusModebooleanMissing defaults to false.
focusAllowedPackagesarray / null / omittedCritical three-way behavior; see below.

Timestamps

Use UTC in the file. IST (UTC+05:30) is a display/local-time concern, not a separate task timezone field.

07:00 IST
→ 01:30Z

2026-10-04T10:44:00+05:30
→ 2026-10-04T05:14:00.000Z

For software, compare parsed instants/epoch values rather than arbitrary timestamp strings.

Status on import

  • scheduled + future end → stays scheduled
  • scheduled + past end → becomes skipped, with updatedAt = planNow
  • active + future end → becomes scheduled
  • active + past end → becomes skipped
  • completed / skipped / overdue → preserved

Importing a past task is different from FocusFlow's normal local overdue sweep.

focusAllowedPackages — do not get this wrong

  • Omitted → use the global allowedInFocus list.
  • null → also use the global list.
  • Array with packages → use this task-specific list.
  • [] → all apps allowed for this task.
Important: task-level focusAllowedPackages: [] is not the same thing as the legacy __block_all__ preset sentinel.

Reminders

"reminders": [
  {
    "id": "reminder-001",
    "taskId": "task-001",
    "offsetMinutes": -5,
    "type": "pre-start"
  }
]

Types: pre-start, at-start, post-start. Optional notifId may be string/null. Max 100 reminders per task.

Reminder meaning

Task.reminders[] is preserved as task data, but it does not drive Android notification scheduling in V1. Notification timing is derived from task times/status.

Canonical files should simply emit a valid array, commonly [].

3. Portable settings

These are the V1 settings that belong in a portable backup. The names here are the actual wire names.

Rule: a recognized setting that is present and valid overwrites the destination value. A recognized setting that is absent leaves the destination value alone. Recognized collections are overwritten wholesale, not merged item-by-item.

Daily allowance

"dailyAllowanceEntries": [
  {
    "packageName": "com.example.video",
    "mode": "time_budget",
    "budgetMinutes": 30
  }
]

Modes: count, time_budget, interval. Numeric fields: countPerDay, budgetMinutes, intervalMinutes, intervalHours. Canonical files use packageName.

Presets

"blockPresets": [
  {
    "id": "social-apps",
    "name": "Social apps",
    "packages": ["com.example.social"]
  }
]

Both allowed-app presets and block presets use id, name, and packages[]. The legacy __block_all__ sentinel belongs only to allowed-app presets and should not be invented or confused with task focus lists.

Recurring schedules and greyout windows

Recurring schedule:

{
  "id": "evening",
  "name": "Evening block",
  "packages": ["com.example.social"],
  "days": [1, 3, 5],
  "startHour": 21,
  "startMin": 0,
  "endHour": 22,
  "endMin": 30,
  "enabled": true,
  "vpnEnabled": false,
  "vpnPackages": []
}

Day numbers: 1=Sunday … 7=Saturday. Hours are 0..23, minutes 0..59. Overnight windows are allowed when end time is earlier than start time.

Greyout rule: greyoutSchedule contains two kinds of windows. Windows without scheduleId are user-authored portable windows. Windows with scheduleId are derived copies. On import, preserve the user-authored ones, discard derived ones, then regenerate the derived windows from recurringBlockSchedules.

wakeUpTime/sleepTime use HH:mm. chronotype: morning, midday, afternoon, evening, night, flexible. breakStyle: short_frequent, balanced, long_infrequent, no_break. weeklyReviewDay: sun … sat.

4. What is not portable

A correct `.focusflow` file is not a dump of every device state.

Never apply

These 21 legacy/live-state keys must never change the destination device, even when present in an old V1 file:

Accept/ignore for compatibility

weekStartDaydefaultReminderOffsetslauncherPinnedPackagesbeginnerModetipsCardDismissedtipsCardFirstShownAtlastShownStreakMilestonependingAchievementCelebrationpendingPresets

Wallpaper: launcherWallpaperUri and overlayWallpaper are device-local external references. Keep the destination's local value; do not import a dangling URI from another device. Report it as unresolved when applicable.

Consent: onboardingComplete and privacyAccepted remain destination-local.

Also not stored in the file: active Focus Sessions, PIN secrets, live enforcement state, AlarmManager registrations, PendingIntents, posted notifications, notification channels, and reminder ledgers. These are recreated or remain local rather than being imported from the backup.

5. Import rules

These are the rules an implementation, validator, or AI agent should follow when handling a V1 file.

Reject the whole file

  • Invalid/malformed JSON or UTF-8.
  • Top-level value is not an object.
  • Wrong or missing kind.
  • settings is not an object.
  • tasks is not an array.
  • Present version is not 1.
  • Duplicate JSON keys anywhere.
  • Any hard parser limit is exceeded.
  • Duplicate task IDs occur inside the same tasks[] array.

Task-level problems

  • Bad task timestamp → that task is invalid.
  • Unknown status/priority → that task is invalid.
  • Bad schedule/window → that object is dropped with a warning.
  • Bad package entries → invalid entries may be dropped with a warning.
  • Bad reminder items → invalid reminder items are dropped with a warning.
  • The remaining valid tasks can still continue through import.

Merge vs Replace

SituationMERGEREPLACE
New task IDInsert it.Insert it.
Same ID + identical contentSkip as identicalDuplicate.Existing task is deleted as part of replacement, then incoming task is inserted.
Same ID + different contentAbort entire import before mutation. Show ID_CONFLICT and suggest Replace.No conflict check is needed because the task list is replaced.
Existing tasks not in backupKeep them.Delete them from the task list.
History / analyticsUntouched.Untouched.

Replace is specifically “replace tasks”, not “reset the whole app”. An active Focus Session blocks Replace.

Repeated import

Deliberately importing the same file again is allowed. Identical task IDs become no-ops; settings are re-applied according to their field rules. There is no permanent backup-level “already imported” lock.

Package references

Use exact Android package IDs. Do not substitute labels/names. A referenced package does not have to be installed on the destination; valid references may remain dormant/unresolved.

Canonical package regex:

^[A-Za-z][A-Za-z0-9_]*(\.[A-Za-z0-9_]+)+$

What happens to alarms?

Alarm registrations are not stored in .focusflow. After persistent tasks are restored, FocusFlow rebuilds the task-end alarms and task-relative reminder notifications from the restored task data and current device capabilities.

This is why editing a backup file never requires you to invent PendingIntents or Android alarm IDs.

6. Practical limits

Stay inside these limits when generating or validating a file.

File

  • 8 MiB maximum UTF-8 input
  • 12 maximum JSON nesting depth
  • 2,000,000 maximum JSON nodes
  • Strict duplicate-key detection

Tasks / lists

  • 20,000 tasks
  • 5,000 package-list items
  • 5,000 blocked words
  • 5,000 greyout windows
  • 500 presets
  • 500 recurring schedules
  • 1,000 daily-allowance entries
  • 100 tags / task
  • 100 reminders / task

Strings

  • 20,000 general string chars
  • 1,000 title chars
  • 100 tag chars
  • 255 package-name chars
  • 200 blocked-word chars
  • 128 task/reminder ID chars

8. Rules for a builder or integration

These are the few implementation rules an agent actually needs to remember.

When generating

  • Emit kind: "FocusFlowBackupV1" and version: 1.
  • Use the exact TS V1 wire names from the settings table.
  • Emit canonical task timestamps as UTC .sssZ.
  • Generate unique task IDs.
  • Do not emit the 21 never-apply live-state keys.
  • Do not emit dangling wallpaper paths.
  • Use valid package identifiers.
  • Keep presetSections and summary descriptive, not authoritative.
  • Write normal UTF-8 JSON with no comments or trailing commas.
  • Save with the .focusflow extension.

When reading

  • Validate the envelope before using settings/tasks.
  • Reject duplicate keys and duplicate task IDs.
  • Accept missing version as V1.
  • Normalize timestamps before comparison/storage.
  • Apply only the recognized portable settings.
  • Never let an imported live-state key weaken destination protections.
  • Distinguish user greyout windows from derived schedule copies.
  • Do not schedule from Task.reminders[].
  • Treat malformed individual tasks according to task-level validation rules.
  • Remember: persistent file data ≠ device runtime state.
Interoperability goal: a developer, normal user, or AI agent should be able to look at this page, construct a valid V1 document, and understand exactly what FocusFlow will preserve, ignore, transform, or reject—without needing to understand FocusFlow's Kotlin internals.
