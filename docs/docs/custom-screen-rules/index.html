Custom Screen Rules

Block one screen inside an app instead of the whole app. Capture it, pick the elements that identify it, test it, then switch it on.

Beta. Screen rules read the element tree an app exposes to Android’s accessibility service. Apps change their screens and some hide elements, so a rule can stop working after an app update. FocusFlow never takes a screenshot; the Screen view is rebuilt from element positions and text.

What a rule is

A custom screen rule blocks one screen inside an app instead of the whole app. It works like the built-in Block YouTube Shorts and Block Instagram Reels switches: it only blocks while that screen is actually showing, not whenever the app is open. Use it for a feed, a tab or a player in any other app.

Make a rule in three steps

  1. Capture

    Custom Screen Rules → Add rule from screen → Start. Switch to the app and open the exact screen you want to block. If it is a tab or a mode (the Reels tab, the Shorts player), tap it first so it is the highlighted one, and leave it showing until the countdown ends. FocusFlow scans what is on screen at that moment and tells you when it is done.

  2. Choose elements

    Open Choose element. On the Screen view, tap the part of the screen that only appears on the screen you want blocked, then Add this element. The Text list tab shows the same elements with a search box.

  3. Test, save and turn on

    Name the rule. Before saving, use Test this rule in the editor: tap Start, switch to the app, open the screen with its tab selected, and wait. It says whether the rule would block that screen and what each element found. Save it, then switch it on in My rules. A new rule starts switched off.

Select it first, then capture

FocusFlow can only tell if you show it the screen while it is selected. Open the screen you want blocked, tap its tab so it is highlighted, and capture then. Elements that are hidden, off screen or on another page are ignored, and a tab you captured while it was highlighted only counts while it is highlighted. If you capture from the home screen, the rule cannot know which screen you meant.

Picking good elements

TipWhy
Prefer an idAn id such as reel_recycler survives most app changes. Elements drawn faintly on the Screen view have no id or text and are weaker.
Be careful with textText can change with the language or the content. A fixed label such as a tab name is safe; a video title is not.
Use one to three elementsMatch all means every element must be present (stricter). Match any means one is enough (broader).
Test both waysUse Test this rule on the target screen: it should say the rule would block it. Then test one of the app’s other screens (home, search, profile): it should say it would not. If it would, the rule matches something that is on every screen — pick again from a capture taken with the target screen selected. If a tab shows “found, but not selected”, select that tab first or turn off Only when selected.

Optional: let an AI assistant write it

You do not have to use an assistant; it is only a shortcut for writing the rule. FocusFlow checks every imported rule and refuses invalid ones.

  1. Export the scan

    Capture the screen as above (with the screen or tab already selected), open Choose element and tap Export. This shares a text list of every visible element on that screen.

  2. Copy the prompt

    Tap Copy screen-rule prompt on the in-app guide page.

  3. Give both to an AI assistant

    Paste the prompt, then the scan, then one sentence about what to block. The scan contains text that was visible on that screen, so check it before sharing.

  4. Paste the answer back

    Copy the JSON it returns. In Custom Screen Rules open Import / export, paste it, and review. Imported rules start switched off until you turn them on.

  5. Test before turning on

    In My rules tap the imported rule and use Test this rule once on the target screen (it should say it would block) and once on another screen of the app (it should say it would not).

Import format

Rules are shared as JSON. Matcher fields are viewIdSuffix, className, textContains, descContains and selectedOnly; every field you include must match the same element, and a matcher with only className is refused as too broad.

{
  "format": "focusflow.screenrules",
  "version": 1,
  "rules": [
    {
      "name": "Example: Reels tab",
      "packageName": "com.example.social",
      "matchMode": "ALL",
      "matchers": [
        { "viewIdSuffix": "reel_recycler" },
        { "descContains": "Reels", "className": "android.widget.ImageView", "selectedOnly": true }
      ]
    }
  ]
}

Limits

LimitValue
RulesAt most 30 rules in total.
Matchers1 to 5 matchers per rule.
Field lengthEach field is at most 200 characters.
Import sizeAt most 65,536 characters per import.
Imported rulesAlways start switched off.
